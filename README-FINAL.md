# 招投标文件智能检查清单生成系统

> 基于AI原生能力的智能系统，达到S级标准

## 系统简介

本系统是一个基于Claude AI能力的招投标文件智能检查工具，能够自动从招标文件中识别：

- **废标条款**：不满足会导致投标被否决的条款
- **建议性要求**：不满足不会直接废标，但有助于提升规范性或评分的要求

### 核心特点

- **AI原生**：基于Claude AI能力，最少化代码
- **知识驱动**：规则和示例存储在知识库中
- **持续学习**：通过Few-Shot不断优化
- **易于维护**：更新知识库即可升级系统
- **S级标准**：识别率≥95%，多文档验证通过

## 快速开始

## 核心组件

### 1. Claude Code Skills

位置：`.claude/skills/`

| Skill | 功能 |
|-------|------|
| check-bidding-doc.md | 一键检查招标文件 |
| extract-clauses.md | 提取特定类型条款 |
| validate-clauses.md | 验证已有清单 |
| compare-versions.md | 对比不同版本 |

### 2. 知识库

位置：`data/knowledge/`

| 文件 | 内容 |
|------|------|
| rules.md | 识别规则、关键词库、分类规则 |
| examples.md | 典型示例、处理技巧、常见错误 |

### 3. MCP配置

位置：`mcp-config.json`

用于配置Jina MCP服务器，提供文档处理能力。

## 使用指南

### 基础使用

```
用户：请检查这个招标文件：招标文件.docx

Claude：
1. 正在读取文档...
2. 分析文档内容...
3. 识别废标条款...
4. 生成检查清单...

已识别16个废标条款，8个建议性要求
检查清单已保存到：data/output/检查清单.md
```

### 高级用法

```
# 只提取废标条款

# 验证已有清单
用户：验证这个清单是否正确：清单.json

# 对比版本
用户：对比这两个版本的差异：v1.docx v2.docx
```

## 输出格式

### 废标风险检查表

| 检查项 | 类型 | 原文页码 | 原文关键信息 | 逻辑解释 | 参考页码 | 额外说明 |
|--------|------|----------|--------------|----------|----------|----------|
| 提交投标保证金 | 文件 | 8 | 投标人未按招标文件要求提交投标保证金的，其投标将被否决。 | 必须按要求提交投标保证金，否则投标将被否决。 | | |

### 建议项清单表

| 检查项 | 类型 | 原文页码 | 原文关键信息 | 逻辑解释 | 参考页码 | 额外说明 |
|--------|------|----------|--------------|----------|----------|----------|
| 采用A4纸打印 | 格式 | 20 | 投标文件原则上应采用A4纸打印。 | 建议采用A4纸打印，不满足通常不会直接导致废标。 | | |

## 质量等级

- **S级**：所有条款正确识别 + 多文档验证（≥90分）
- **A级**：复杂类型识别率≥90% + 参考信息（≥85分）
- **B级**：复杂类型识别率≥60% + 页码（≥75分）
- **C级**：识别明确条款（<75分）
