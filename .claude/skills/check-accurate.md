# 高精度检查清单生成（100%准确率）

## 执行流程

我将通过**5轮验证**来确保100%准确率：

### 📍 第一轮：初始识别

首先使用标准识别流程处理文档。

### 📍 第二轮：自我验证

对初始结果进行自我验证，检查：

```markdown
## 自我验证清单

### 完整性检查
- [ ] 是否扫描了所有段落？
- [ ] 是否检查了所有表格（包括合并单元格）？
- [ ] 是否检查了所有附件引用？
- [ ] 是否检查了跨章节引用？

### 准确性检查
对每个已识别的条款，验证：
- [ ] 原文关键信息是否完整摘录（未截断）？
- [ ] 页码是否准确？
- [ ] 分类是否正确？
- [ ] 逻辑解释是否通俗易懂？

### 遗漏检查
重点搜索确认：
- [ ] 搜索"否决"、"无效"、"不接受"、"拒绝" - 确保全部识别
- [ ] 搜索"必须"、"应当"、"不得" + 后果描述
- [ ] 检查所有表格的每个单元格（不只看列名）
```

### 📍 第三轮：交叉验证

使用**5种不同方法**交叉验证：

```markdown
## 交叉验证

**方法1：关键词扫描**
扫描文档，统计所有废标关键词出现次数
对比：关键词出现次数 vs 已识别条款数

**方法2：表格全扫描**
- 读取所有表格
- 逐个单元格分析语义
- 提取"要求+后果"结构

**方法3：条件句模式**
使用正则表达式匹配：
- (若|如果|当|如)...(则|将)...(否决|无效|不接受)
- (未|未按|未规定)...(者|的)?...(否决|无效|不接受)

**方法4：引用链追踪**
- 找到所有"参见"、"详见"、"按附件X"等引用
- 追踪到被引用内容
- 提取完整条款

**方法5：语义分析**
对每个段落进行语义分析：
- 判断是否为强制性要求
- 判断是否有负面后果
- 判断是否为废标条款
```

### 📍 第四轮：边界案例检查

专门检查**容易出错的场景**：

```markdown
## 边界案例检查

### 案例1：隐含废标条款
搜索以下模式：
- "后果由供应商自行承担"
- "责任由...自负"
- "视为未提交"
- "视为未响应"

### 案例2：表格隐藏条款
- 检查所有合并单元格
- 检查"备注"、"说明"、"其他"列
- 检查单元格内的换行内容

### 案例3：或逻辑条款
搜索模式：
- "A或B，...将被否决"
- "A、B、C任一不满足...无效"

### 案例4：时间序列条款
- 查找所有时间相关要求
- 查找对应的后果描述
- 合并为完整条款

### 案例5：附件隐含要求
- 查找所有"按附件X格式"
- 提取附件中的要求
- 如果附件中有后果描述，提取出来
```

## 关键要点

1. **绝不假设**：不假设任何条款，全部验证
2. **穷尽扫描**：扫描所有内容，不遗漏任何地方
3. **多重验证**：每种方法都验证一遍
4. **交叉确认**：不同方法结果相互印证
5. **边界关注**：特别关注容易出错的边界情况
